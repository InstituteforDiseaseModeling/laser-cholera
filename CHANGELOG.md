# Changelog

## Unreleased

- 🐛🧪 R-vs-Python parity fix: `_calc_log_likelihood_nb` now mirrors the three-branch zero-prediction handler in `MOSAIC::calc_log_likelihood_negbin` (R reference v0.47.5). Cells with `estimated <= 0 AND observed > 0` apply the R proportional penalty `-observed * log(1e6)`; cells with `estimated <= 0 AND observed == 0` contribute exactly 0 (perfect-match zero); all other cells go through the standard NB / Poisson kernel on `max(estimated, 1e-10)`. The previous Python implementation only had the third branch, which floored `est` at `1e-10` and then evaluated the NB log-PMF — giving ~-95 per `obs=4, est=0` cell where R gives ~-55, a ~50% LL drift on any fixture with `est=0` cells (in particular any all-zero-deaths channel against non-zero observations). The drift was invisible against earlier (pre-v0.45.3) MOSAIC releases because that older R also lacked the handler. New tests in `tests/R/` cross-check R vs Python on shared fixtures and now agree to ~1e-8 on the total LL across all 24 scenarios. Side benefit: the perfect-match zero-data deaths channel now returns byte-precise 0, so the two assertions in `tests/test_calc_model_likelihood_obs_weights.py` that were loosened to `1e-7` to accommodate the `~ -4e-10` Poisson floor leak have been tightened back to `1e-12`, matching the R `testthat` tolerance.
- 🧪📝 Add `tests/R/` — R-vs-Python parity tests for `calc_model_likelihood` (issue #86 acceptance criterion #7). 24 testthat cases across three categories: NB core (9), per-observation weights (9), shape terms (6 — cumulative / WIS / custom quantiles / custom timepoints / both / kitchen-sink). Each test builds an R-side fixture, calls `MOSAIC::calc_model_likelihood` (canonical R), calls Python `laser.cholera.calc_model_likelihood` through `reticulate`, and asserts agreement to `1e-8` (NB core + obs-weights) or `1e-5` (shape terms — R / scipy use independent special-function paths). `tests/R/run_tests.sh` is the CLI driver that prints a version banner (R, MOSAIC, reticulate, testthat, laser-cholera + which Python interpreter), forces reticulate onto the project's editable venv via `RETICULATE_PYTHON`, and exits non-zero on failure. `helper-setup.R` ships `py_calc_ll(...)` (one-call cross-language wrapper) and `expect_ll_match(...)` (tolerance-aware comparator). The peak-timing / peak-magnitude shape terms are intentionally not cross-checked here because the R `MOSAIC` signature consumes a `config` list while Python takes flat `epidemic_peaks` / `date_start` / `date_stop` arguments — a tailored translator is a follow-up. Minimum required MOSAIC version is `0.45.3` (the obs-weights port); tests skip cleanly with an actionable install message on older installs.
- ✨🦺🧪 Per-observation confidence weighting for the NB core of `calc_model_likelihood` (issue #86). Adds two optional `(n_locations, n_time_steps)` matrix arguments — `weights_obs_cases` and `weights_obs_deaths` — that carry per-cell trust in `[0, 1]` (NaN permitted, treated as zero). Brings the Python implementation to parity with MOSAIC v0.45.3 (commit `7a265b1d`) so the Coiled/Dask worker no longer diverges from the local R PSOCK calibration path. Semantics ported verbatim from `R/calc_model_likelihood.R`: (1) `None` or all-ones-on-finite-obs rows route through the legacy unweighted code path for byte-identical results — guaranteed by the new `weights_obs_row_trivial` classifier; (2) non-trivial rows go through a mass-preserving renormalisation (`weights_obs_effective`) so each location's total NB log-likelihood mass equals the unweighted equivalent, only the _shape_ of which cells are trusted changes; (3) the observation gate on the weighted path is ESS-style (`sum(weights_obs_row[finite, positive-weights_time]) >= 3`) and cases / deaths gate independently; (4) the NB dispersion `k` is estimated from the _same_ weights used to score (k-coherence). Shape terms (peak / cumulative / WIS) remain unweighted in v1, matching the R contract. Input validation rejects non-matrix, wrong-shape, and negative-entry inputs with `ValueError` messages that name the offending parameter. New tests in `tests/test_calc_model_likelihood_obs_weights.py` mirror all eight R `testthat` cases in `MOSAIC-pkg/tests/testthat/test-calc_model_likelihood_obs_weights.R` plus five direct unit tests on the trivial-row classifier and an explicit `None`-vs-omitted regression. The two new public helpers (`weights_obs_row_trivial`, `weights_obs_effective`) live alongside `mask_weights` in `calc_model_likelihood.py`.
